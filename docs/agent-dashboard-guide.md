# Working with the example dashboards (agent guide)

This repo ships two copies of the same dashboard, and both are generated by
hand from the live-tuned version in a real Grafana instance. Keep this guide
in sync if that workflow changes.

- `src/dashboards/overview.json` — bundled with the plugin itself via the
  `includes` entry in `src/plugin.json`. Users import it from the data
  source's **Dashboards** tab in any Grafana instance.
- `provisioning/dashboards/json/aws-cost-explorer.json` — loaded automatically
  by the local `docker compose` dev environment via
  `provisioning/dashboards/dashboards.yml`.

The two differ in exactly one way: the bundled copy references the
datasource as `"${DS_AWS_COST_EXPLORER}"` (a template input, resolved at
import time), while the provisioning copy references the fixed dev
datasource `"uid": "aws-cost-explorer"` declared in
`provisioning/datasources/datasources.yml`. Everything else — panels,
targets, `fieldConfig`, `options`, layout — should stay identical between the
two files.

## If you're given a raw dashboard JSON to bundle

A dashboard exported straight from a modern Grafana instance's API or URL
(look for `"apiVersion": "dashboard.grafana.app/v2beta1"`, `"kind":
"Dashboard"`, and a `spec.elements`/`spec.layout` shape) is the **raw stored
resource**, not the shareable export format. It will not work as a
provisioned or bundled dashboard as-is. Convert it to the classic dashboard
schema first:

- `spec.elements.panel-N` → an entry in a flat `panels` array, with `id`,
  `title`, `description`, `type` (from `vizConfig.group`), `fieldConfig` and
  `options` (from `vizConfig.spec`), and `targets` (from
  `data.spec.queries[].spec.query`, hoisting the query's `spec` fields
  directly onto the target alongside `refId` and `datasource`).
- `spec.layout.spec.items[].spec` (`element`, `x`, `y`, `width`, `height`) →
  `panel.gridPos` (`x`, `y`, `w`, `h`). The grid units line up directly.
- `transformations: [{"kind": "...", "spec": {"id": ..., "options": ...}}]`
  → `transformations: [{"id": ..., "options": ...}]` (drop the `kind`/`spec`
  wrapper).
- `spec.annotations` → `annotations.list` (`"builtIn": true` becomes
  `"builtIn": 1`).
- Drop generic query-editor scaffold fields that don't exist on this
  plugin's `CostQuery` type (see `src/types.ts`) if they leak in — e.g.
  `direction`, `editorMode`, `expr`, `queryType`. They're artifacts of the
  Grafana query row UI, not part of this datasource's query model.
- Set `schemaVersion` to match the other dashboard JSON in this repo (bump
  both together if you deliberately move to a newer Grafana schema).

For the **bundled** copy specifically, follow [Grafana's guide on including
dashboards in data source
plugins](https://grafana.com/developers/plugin-tools/how-to-guides/data-source-plugins/include-dashboards.md):
add `__inputs` (one `datasource` input, e.g. `DS_AWS_COST_EXPLORER`, with
this plugin's `pluginId`) and `__requires` (this datasource plus every panel
type used and the Grafana version), and point every panel/target
`datasource.uid` at `"${DS_AWS_COST_EXPLORER}"` instead of a real uid.

## Before committing or opening a PR

CI's "Build, lint and unit tests" job runs `npm run format:check`, which
includes every `provisioning/**/*.json` and `src/**/*.json` file. **Never
regenerate or hand-write dashboard JSON with a plain serializer** (e.g.
Python's `json.dump`) — its output will not match this repo's Prettier
style and the format check will fail. Instead:

1. Write or edit the JSON file.
2. Run `npx prettier --write <path>` (or just `npm run format:check` to spot
   it, then `--write`) before committing.
3. Locally mirror the CI job before pushing:
   ```bash
   npm run typecheck
   npm run format:check
   npm run lint
   npm run test:ci
   npm run build
   ```
4. If you changed `src/plugin.json` (e.g. the `includes` array), also run
   the `validate-plugin` skill — it builds a zip and runs
   `@grafana/plugin-validator` against it, which independently checks the
   `includes` metadata and schema.
5. Remind whoever is testing manually that `plugin.json` changes require a
   Grafana restart to take effect.
